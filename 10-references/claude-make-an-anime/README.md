# مرجع: claude-make-an-anime

تحليل كامل لمستودع [makevoid/claude-make-an-anime](https://github.com/makevoid/claude-make-an-anime)، وهو إضافة (Plugin) لـ Claude Code تحوّل قصة مكتوبة إلى أنمي كامل بالصوت.

| الحقل | القيمة |
|---|---|
| النسخة المحللة | 0.6.0، commit `adc1a76` (2026-11-08) |
| الترخيص | MIT، فيجوز نقل الكود مع ذكر المصدر |
| الحجم | حوالي 230 ملفاً وقرابة 13 ألف سطر: Ruby وJS (p5) وPython وSwift واختبارات RSpec |
| التوليد | عبر Fal.ai: GPT Image 2.6، وMiniMax H3 (فيديو)، وSeedance (اختياري)، وElevenLabs (صوت وموسيقى ومؤثرات)، وWhisper |

> **القرار:** نأخذ الأفكار والأدوات، ولا نثبّت الإضافة كما هي. هي أفقية 16:9 فقط، ولا تدعم العربية جيداً، وجزء منها يحتاج macOS (التفاصيل أدناه).

ملفات هذا المرجع:
- [`prompt-lessons.md`](prompt-lessons.md): دروس البرومبتات والإنتاج المجرّبة.
- [`portable-tools.md`](portable-tools.md): الأدوات القابلة للنقل وحالة نقلها إلى مستودعنا.

## 1. مسار الإنتاج عندهم

```
قصة ← خطة PLAN.md (مع تكلفة بعدد الاستدعاءات) ← موافقة المستخدم ← شيتات الشخصيات والأماكن
   ← الأصوات (قبل الحركة: طول الجملة يحدد طول اللقطة) ← الموسيقى ثم خفضها تحت الكلام
   ← إطار أول لكل لقطة ← تحريك كل لقطة (H3 + اتجاه كاميرا + صوت المتكلم لمزامنة الشفاه)
   ← طبقة p5: الترجمة والعناوين والنصوص ← المؤثرات الصوتية ← المؤثرات البصرية ← مراجعة
```

المشهد الواحد يُسمّى RUN، وله مجلد برومبتات `prompts/<run>/` ومجلد مخرجات `output/<run>/` فيه ملف `manifest.json`. كل خطوة مخزنة مؤقتاً، فأي تعديل يعيد فقط ما يتأثر به.

## 2. نقاط القوة

### حماية المال
- **بوابة الموافقة:** يُحسب بصمة (SHA-256) لملف `PLAN.md` وتُسجّل مع موافقة المستخدم. أي تعديل على الخطة يُبطل الموافقة، ولا يُرسل أي طلب مدفوع بدونها.
- **إيصالات الطلبات:** بصمة (نقطة النهاية + المدخلات) تُحفظ كإيصال **قبل** انتظار النتيجة. إذا انقطع الاتصال يُستأنف الطلب نفسه بدل الدفع مرتين، وإعادة نفس المدخلات تعيد نفس النتيجة مجاناً.
- **رفع الملفات** مخزن مؤقتاً حسب بصمة محتوى الملف.
- **عزل المفتاح:** خادم MCP صغير يحقن مفتاح الـ API في العملية المنفذة فقط، ويحجبه من المخرجات، ويقبل مهاماً وخيارات من قائمة مسموحة فقط.

### ثقافة هندسية
- كل خطأ إنتاج حقيقي صار اختباراً يمنع تكراره، وعددها حوالي 111 اختباراً. أمثلة:
  - إبطاء اللقطة كان يسقط إطاراً.
  - `-shortest` في FFmpeg أسقط 4 إطارات.
  - تسرّب تنسيق الرسم بين الإطارات في p5.
  - الذاكرة وصلت 40GB بدون `autoreleasepool`.
- التوثيق صريح في ذكر حدوده، مثل: "معايرة على عينتين فقط"، و"الاختبارات لا تثبت سلوك الوكيل".

### أدوات مراجعة آلية مجانية
| الأداة | ماذا تفحص |
|---|---|
| `review:camera` | حركة الكاميرا الفعلية (زوم/تحريك) بين أول وآخر إطار مقارنةً بالمطلوب، مع شريط إطارات لكشف القطع المخفي |
| `review:believable` | يرفض الحركة القوية (ركض، ضرب) على الشاشة الخضراء، ويقيس سرعة الأرض لكشف "الجري في المكان" |
| `dialogue:timeline` | كل جملة منطوقة داخل لقطتها ولا تعبر قطعاً |
| `review:dialogue` | Whisper يكشف الكلمات الناقصة أو المكررة (مدفوع) |
| `audio:seams` | الانتقالات المفاجئة في الموسيقى بين المشاهد |

## 3. نقاط الضعف بالنسبة لنا

1. **أفقي فقط:** مقاس GPT Image مثبت على `16:9`، وتجميع اللقطات على 1920×1080. لا يدعم 9:16.
2. **العربية:**
   - `Dialogue.spoken()` يحذف كل ما ليس `[a-z0-9]`، فمراجعة النطق العربي تنجح دائماً بلا فحص.
   - `Anim.cues` يحذف الحروف غير اللاتينية، فمزامنة الكلمات العربية تفشل.
   - الكاريوكي يُرسم من اليسار لليمين فقط.
   - Whisper يفترض الإنجليزية ما لم يُحدَّد `language_code`.
3. **البيئة:** يحتاج Ruby وNode وPython وChrome. المؤثرات البصرية (Swift/Core Image) والبحث عن الخطوط تعمل على macOS فقط.
4. **التكلفة:** كل الفيديو عبر H3 مدفوع. مثال 74 ثانية احتاج حوالي 23 لقطة فيديو و22 صورة و22 تسجيلاً صوتياً.
5. **متخصص بالأنمي والدراما**، لا بإعلانات الشركات والموشن جرافيك.
6. **ملاحظات انتباه:**
   - تناقض في التوثيق: 768P مقابل 1080P كدقة افتراضية.
   - في `live_spec.rb` تعليق موجّه لوكلاء الذكاء الاصطناعي يطلب تعديل الكود.
   - الوكيل نفسه هو من يسجّل الموافقة، فهي تمنع التسرّع لكنها لا تثبت أن المستخدم وافق.
   - ملفات الإعداد `config/generations.rb` تُنفَّذ ككود Ruby، فلا تُستخدم إلا مع مشاريع موثوقة.
